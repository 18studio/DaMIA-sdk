# DaMIA SDK

Асинхронный Python SDK и CLI для сервисов DaMIA. Реализованы 61 GET-метод восьми сервисов и общий HTTP-транспорт; команды CLI пока остаются заглушками.

Проектный дизайн, настройки, HTTP-клиент, CLI и план разработки описаны в [docs/PROJECT.md](docs/PROJECT.md).

## Разработка

Требуются Python 3.11+, [uv](https://docs.astral.sh/uv/) и Make:

```bash
make sync
uv run damia --help
uv run damia version-info
make check
```

Зависимости и настройки находятся в `pyproject.toml`, зафиксированные версии — в `uv.lock`. Sentry доступен как необязательная зависимость: `uv sync --extra sentry`; интеграция и логирование SDK ещё не реализованы.

Настройки загружаются из окружения только явно, через `DamiaSettings.from_env()`. Например, `DAMIA_FNS_KEY`, `DAMIA_BASE_URLS__FNS` и `DAMIA_TIMEOUT__READ`. Сервисные методы выполняют GET-запросы через общий транспорт и возвращают `HttpResponse` с `status_code`, `data`, `body` и `json()`. **Вызовы SDK могут быть платными или изменять состояние**, несмотря на использование GET. Повторы и кеширование на уровне сервисных методов не включаются автоматически, даже если они разрешены в настройках транспорта. Низкоуровневому транспорту нужны явные флаги `allow_retry` и `allow_cache`; для кеша также обязателен `cache_validator`. Подробности — в [дизайне проекта](docs/PROJECT.md#http-транспорт).

## CLI

В CLI доступны группы `fns`, `rosstat`, `banks`, `scoring`, `procurement`, `arbitration`, `fssp` и `spk` и заготовки команд для 61 метода SDK:

```bash
uv run damia fns --help
uv run damia fns egr --help
uv run damia rosstat multbalance --help
```

Параметры команд получены из сигнатур методов SDK; подчёркивания в именах заменяются дефисами, например `nalogbi_file` → `nalogbi-file`. Пока команды **ничего не отправляют и не возвращают данные**: они выводят сообщение «пока не реализована» в stderr и завершаются с кодом 1. Настройки окружения для таких заглушек не загружаются. Опции `--output`, выполнение SDK, кеширование и повторы ещё предстоит реализовать. Не передавайте в командной строке секреты или реальные персональные данные.

## Тестирование с Prism

В одном терминале запустите Prism для ФНС (нужны Node.js и `npx`):

```bash
make prism-fns
```

В другом запустите локальный тест с Hypothesis:

```bash
RUN_PRISM_TESTS=1 uv run --locked pytest -m prism
```

Этот первоначальный тест обращается только к `127.0.0.1`, использует синтетические данные и проверяет HTTP-интерфейс Prism, а не SDK. По умолчанию он пропускается. Если Prism запущен на другом порту, передайте его в `PRISM_TEST_PORT`, например `RUN_PRISM_TESTS=1 PRISM_TEST_PORT=4011 uv run --locked pytest -m prism`. Подробнее о mock-сервере: [docs/swagger/README.md](docs/swagger/README.md).

### E2E-тесты SDK и CLI

```bash
make test-e2e-sdk  # все 61 метода SDK
make test-e2e-cli  # все 61 команды CLI
make test-e2e      # оба набора
make test-unit     # прочие тесты, без e2e
```

Тесты самостоятельно запускают восемь локальных Prism 5.5.0 через `npx` на свободных портах и завершают процессы после тестирования; Node.js и `npx` обязательны. Используются только синтетические значения. Для Python-процесса тестов и дочернего процесса CLI включён запрет внешних сетевых адресов; настройки и реальные ключи `DAMIA_*` из окружения CLI не наследуются. Это тестовая защита на уровне Python, а не замена сетевой песочнице ОС.

E2E-наборы проверяют адрес и параметры через локальный прокси, ответ Prism и результат SDK или CLI. Методы SDK возвращают `HttpResponse`, содержащий `data` и `status_code`. Для файлов CLI-тесты предполагают будущую опцию `--output`, которая ещё не реализована. Hypothesis генерирует синтетические параметры и ключи; сокращение примеров при ошибках отключено для скорости. Сценарии охватывают каждый метод, но не все комбинации его параметров.

Временные тестовые копии спецификаций содержат искусственные ответы для `procurement/zmon`, `spk/report` и `spk/proverki`: без них Prism возвращает 500 из-за неопределённых схем. Исходный Swagger не изменяется, фикстуры не доказывают реальное поведение DaMIA.

Успех SDK e2e с локальным Prism не подтверждает совместимость с реальным DaMIA: спецификации исследовательские и не подтверждены поставщиком. **CLI e2e пока ожидаемо падают**, так как команды CLI остаются заглушками. Они не помечены `xfail` и включены в обычные `make test` и `make check`. Поэтому полный выпуск заблокирован; отдельный SDK-only scope и его gate не утверждены. `make push`, зависящая от `make check`, до реализации CLI не пройдёт.

## Сборка и публикация

Метаданные пакета заявляют Python 3.11+, но полный набор поддерживаемых версий Python и диапазонов зависимостей ещё не проверен. Локально wheel и sdist версии 0.1.0 собраны и их состав и метаданные просмотрены на Python 3.13.14; установка с зависимостями в чистые окружения пока не подтверждена: в локальном offline-кеше отсутствует `aiocache`. Диапазоны зависимостей и необходимость `aiocache` требуют отдельной проверки до выпуска.

```bash
make build       # собрать wheel и sdist в dist/
make push        # проверить проект, собрать заново и опубликовать на PyPI
```

**`make push` действительно публикует пакет в публичный PyPI.** Перед запуском проверьте имя пакета `damia-sdk`, его доступность и права, версию в `pyproject.toml`, содержимое сборки и возможность публичного распространения. Имя выбрано для каркаса; его доступность и права на него не проверялись. PyPI не позволяет повторно загрузить уже опубликованный файл той же версии; при частичной неудаче проверьте состояние проекта на PyPI перед повторной попыткой.

Для локальной публикации настройте токен PyPI в переменной окружения `UV_PUBLISH_TOKEN` или используйте поддерживаемую uv доверенную публикацию. Не записывайте токен в файлы проекта, команду или логи. `make push` собирает артефакты во временный каталог и не отправляет старые файлы из `dist/`. Команда отправляет wheel и sdist, а не весь репозиторий; состав пакета следует проверять перед публикацией.
