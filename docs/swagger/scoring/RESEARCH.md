# Исследование API-Скоринг

## Область и источники

Основной источник — [документация API-Скоринг](https://damia.ru/apiscoring), оригинальный отрендеренный снимок, прочитанный полностью (сейчас недоступен). Дополнительный снимок не использовался. Контекст: [каталог API](https://damia.ru/damapi), [примеры вызовов](https://damia.ru/apicalls?id=1); они не подтверждают форму ответа. Прочитан полный отчёт разведки. Запросы к действующему API не выполнялись; платные вызовы, секреты и данные клиентов не использовались. Реальное поведение не проверено.

## Полный инвентарь и семантика HTTP

Базовый адрес `https://api.damia.ru/scoring`; для каждого метода источник явно указывает GET и JSON. Тело запроса, HTTP-коды, ошибки, заголовки Content-Type, ограничения частоты и пагинация не описаны. При этом источник описывает тарифные квоты и цены; это не описание операционных ограничений частоты. Источник описывает результат метода как JSON, но не подтверждает медиатипы ошибок или конкретный код успеха. Для каждого метода `2XX` с `application/json` и неограниченной схемой выражает интерпретацию документированного JSON-результата как успешного HTTP-ответа; диапазон и медиатип не подтверждены наблюдением статуса или заголовка. `default` оставлен без `content` и не утверждает формат ошибок.

| Метод | Входы помимо key | Источник | Неизвестно и противоречия |
|---|---|---|---|
| GET /score | inn, model, необязательные bNNNN | [описание](https://damia.ru/apiscoring), снимок 48–170 | Форма корня, множество лет/результатов, вложенность показателей, обязательность; пример с `1200` без `b` противоречит правилу bNNNN. |
| GET /info | model | [описание](https://damia.ru/apiscoring), снимок 172–279 | Форма корня, вложенность метрик, тип элементов Год и обязательность. |
| GET /fincoefs | inn, необязательные okved, region | [описание](https://damia.ru/apiscoring), снимок 281–416 | Форма корня и группировки по коэффициентам/годам, обязательность; `Комментарий` в повреждённом комментарии и не подтверждён. |

Формальная обязательность `inn`, `model` и `key` не сформулирована. В OpenAPI `required: false` делает inn/model необязательными для инструментов; глобальное требование security делает key обязательным для инструментов. Обе трактовки не подтверждают серверную проверку обязательности. Ключ — query `key`, строка; является ли он общим для разных сервисов и как выдаётся, не установлено. Не логировать URL с ключом. В коде клиента сохранять ИНН строкой. Для score можно передавать несколько отдельных bNNNN: значения на конец года, в тысячах рублей, целые и могут быть отрицательными. Стандартный список параметров OpenAPI не описывает произвольное семейство отдельных имён, поэтому сгенерированным клиентам нужна дополнительная или ручная поддержка. Их присутствие запускает скоринг по отчётности и введённым данным. Имена встроенных моделей: `_bankrots2016`, `_tech`, `_diskf`, `_problemCredit`, `_zsk`; пользовательские модели также поддерживаются. Для fincoefs пропуск okved/region выбирает значение компании, `0` — все отрасли/регионы; это контекстные значения, а не фиксированные OpenAPI defaults.

## Обезличенные примеры запросов

Примеры иллюстрируют форму запроса и не содержат ключа. `<ИНН>` — заполнитель, а не реальный идентификатор; документация предусматривает отдельную передачу ключа. Запросы не выполнялись.

- `GET https://api.damia.ru/scoring/info?model=_bankrots2016`
- `GET https://api.damia.ru/scoring/fincoefs?inn=<ИНН>`

## Поля и неопределённости

Таблицы полей перенесены в отдельные иллюстративные схемы `*Illustrative` в OpenAPI; не используются как схемы ответов, поскольку даже корневой контейнер не известен; `x-research-notes` соответствующих ответов указывает их как иллюстрации. Пустая схема ответа не устанавливает форму JSON. Схемы сохраняют оригинальные кириллические имена и описанные вложенные показатели и метрики, но не утверждают обязательных свойств. Источник называет `ИНН`, `Модель`, `Год`, `Фин. коэффициент` типом object, хотя описывает их как идентификаторы/годы; для score год может быть `custom`. Их реальные типы не установлены. `info.Год` — массив с неуказанным типом элементов; `Train` и `Test` указаны как объекты, а поля метрик `FPR`, `FNR`, `J`, `AUC`, `Gini` — как строки; вложенность метрик предполагается. Тип модели в источнике написан `logistic regresion`. Nullability неизвестна. Высокое положительное nWoE указывает на положительный вклад в риск; отрицательное соответствует благоприятному признаку. Больший `score.БаллЗнач` означает больший риск, но больший `fincoefs.Балл` означает отсутствие риска; шкалы нельзя отождествлять.

Идентификаторы коэффициентов из источника: `КоэфОборЗапасов`, `ПериодОборЗапасов`, `КоэфОборДЗ`, `ПериодОборДЗ`, `КоэфОборКЗ`, `ПериодОборКЗ`, `КоэфОборАктивов`, `РентАктивов`, `РентСК`, `РентПродаж`, `ЧистРентПродаж`, `КоэфТекЛикв`, `КоэфАбсЛикв`, `КоэфФинАвт`, `КоэфФинЗав`, `КоэфФинЛевер`. Неизвестно, являются ли они значениями поля, ключами карты или частью иной структуры.

## Приоритетный чек-лист SDK

1. С согласия владельца и без раскрытия данных проверить авторизацию, обязательность полей, статусы и ошибки на разрешённых тестовых данных.
2. Получить непустые обезличенные ответы всех трёх методов, включая несколько лет и коэффициентов; уточнить корень, вложенность, nullable и реальные типы идентификаторов.
3. Проверить имена и кодирование bNNNN, отрицательные значения и противоречивый пример с `1200`; поддерживать произвольные документированные строки баланса без предположения о literal bNNNN.
4. Проверить пропуск и `0` для okved/region, настраиваемые модели и точное написание типа модели.
5. Проверить лимиты, пагинацию, повторные вызовы и правила тарификации; не предполагать их отсутствие. Редактировать ключи из журналов и диагностик.
