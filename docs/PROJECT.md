# DaMIA SDK: описание и проектный дизайн

## Назначение и статус

Проект предназначен для создания асинхронного Python SDK и CLI для сервисов DaMIA. SDK должен предоставлять типизированный интерфейс к API, а CLI — использовать те же методы SDK, не дублируя работу с HTTP.

**Текущее состояние:** реализованы общий HTTP-транспорт и 61 GET-метод восьми сервисов по исследовательским спецификациям. Методы могут выполнять реальные платные запросы и менять состояние. Команды CLI остаются заглушками и возвращают код 1. Модели ответов конкретных методов и интеграция Sentry ещё не реализованы. Поведение реального DaMIA не проверялось.

- Имя Python-пакета для публикации: `damia-sdk`; права на имя и его доступность в PyPI ещё не проверены.
- Импортируемый модуль: `damia_sdk`.
- Команда CLI: `damia`.
- Заявленный минимум Python: 3.11; поддерживаемые версии и диапазоны зависимостей ещё не проверены полностью.
- Управление проектом и зависимостями: `uv`; версии для разработки зафиксированы в `uv.lock`.

## Источники API и ограничения

В [`swagger/`](swagger/README.md) находятся исследовательские спецификации OpenAPI 3.0.3 и отдельные отчёты `RESEARCH.md` для восьми сервисов. Они составлены по публичной документации и не проверены реальными запросами к API. Структурная валидация OpenAPI не доказывает соответствия серверу.

В частности, часть форм ответов, типов и HTTP-кодов неизвестна; некоторые примеры и таблицы противоречат друг другу. Для ФНС и Банков POST описан только исследовательскими расширениями `x-post-contract`: транспорт параметров и ключа не установлен. Форматы и поведение нужно подтверждать по мере реализации с помощью поставщика или отдельно разрешённых тестовых запросов. Не генерировать жёсткие модели по непроверенным догадкам.

## Публичный интерфейс

Один асинхронный клиент предоставляет сервисы через свойства и освобождает соединения при выходе из `async with`. Следующий пример при наличии ключа обращается к реальному API — запускайте его только с разрешения владельца:

```python
from pydantic import SecretStr

from damia_sdk import DamiaClient, DamiaSettings

settings = DamiaSettings(fns_key=SecretStr("<API_KEY>"))

async with DamiaClient(settings=settings) as client:
    response = await client.fns.egr(req="<ИНН_ИЛИ_ОГРН>")
    print(response.data)
```

Секреты в исходном коде хранить нельзя; строка выше — только заполнитель. Если ключ нужного сервиса не задан, ошибка должна возникать при обращении к этому сервису, а не блокировать использование остальных.

| Свойство клиента | Сервис | Пример предполагаемого метода |
|---|---|---|
| `client.fns` | ФНС | `egr(req=...)` |
| `client.rosstat` | Росстат | `balance(inn=...)` |
| `client.banks` | Банки | `bankinfo(bankregn=...)` |
| `client.scoring` | Скоринг | `score(inn=..., model=...)` |
| `client.procurement` | Закупки | `contracts(inn=...)` |
| `client.arbitration` | Арбитражи | `dela(q=...)` |
| `client.fssp` | ФССП | `isps(inn=...)` |
| `client.spk` | СПК и проверки Генпрокуратуры | `report(req=...)`, `proverki(req=...)` |

В исходном предложении имена методов сохраняют имена DaMIA для сопоставления с документацией. Публичные аргументы должны быть именованными и типизированными; при необходимости Python-имя отличается от wire-имени и явно сериализуется в имя API. Окончательное решение о сокращённых либо человекочитаемых именах методов ещё можно принять до фиксации публичного API.

### Ответы

Методы возвращают `HttpResponse` с HTTP-статусом, `body`, `content_type` и признаком `from_cache`. Свойство `data` разбирает JSON по Content-Type, возвращает текст для `text/*` и байты для остальных типов. Неизвестные MIME-типы возвращаются как байты; тело целиком загружается в память. При ошибочном JSON метод `json()` и свойство `data` возбуждают `DamiaResponseError`.

`json()` и `data` используют стандартный декодер JSON: дробные числа возвращаются как `float` и могут потерять точность; числа за пределами конечного диапазона `float`, например `1e400`, отклоняются с `DamiaResponseError`. Нестандартные константы `NaN`, `Infinity` и `-Infinity` также отклоняются. Для самостоятельного разбора с сохранением десятичной точности можно использовать `json.loads(response.body, parse_float=Decimal)` с импортами `json` и `Decimal` из `decimal`. Публичная политика точности и чисел за пределами диапазона `float`, включая возможность отдельного lossless API, требует отдельного решения.

- Для подтверждённых структур можно использовать Pydantic-модели; для неясных — сохранять исходный JSON без выдуманной строгой схемы.
- Неизвестные поля ответа нельзя без необходимости терять. ИНН, ОГРН, БИК и номера документов хранить строками; финансовые значения не преобразовывать без подтверждённого контракта.
- Для PDF, ZIP и DOCX нужен отдельный путь обработки бинарного ответа; потоковое скачивание — возможное расширение. Точные MIME-типы и формат ошибок поставщика не установлены.
- Не считать любой HTTP `2XX` гарантированным успехом бизнес-операции. Проверять тело на ошибки только согласно подтверждённому контракту конкретного сервиса.

## Настройки

Проектируемый `DamiaSettings` собирает ключи, базовые адреса, тайм-ауты, повторы, кеш и параллелизм. Настройки логирования и Sentry принадлежат приложению или CLI, а не HTTP-клиенту.

```python
from damia_sdk import DamiaClient, DamiaSettings, TimeoutSettings

settings = DamiaSettings(
    timeout=TimeoutSettings(connect=5.0, read=30.0),
)

async with DamiaClient(settings=settings) as client:
    ...
```

Настройки создаются до клиента и не меняются во время его работы. SDK должен поддерживать явную передачу конфигурации и отдельную явную загрузку из окружения, например `DamiaSettings.from_env()`. Автоматически искать и читать `.env` не следует; если поддержка файла будет добавлена, путь указывается явно.

### Ключи и базовые адреса

Три домена могут использовать разные ключи. Проектируемые настройки предусматривают ключи для ФНС, Банков и сервисов DaMIA, а также возможность переопределить ключ для отдельного сервиса. Общность ключей и тарифов не подтверждена.

Для CLI предполагаются переменные окружения `DAMIA_FNS_KEY`, `DAMIA_BANKS_KEY`, `DAMIA_API_KEY` и сервисные переопределения при необходимости. Каждый базовый адрес должен настраиваться отдельно для настоящего API и тестового сервера. Для CLI приоритет несекретных параметров: явный аргумент → переменная окружения → значение по умолчанию. Источники и приоритеты других настроек необходимо документировать при реализации.

Ключи можно представлять через `SecretStr`, но маскировка `repr` не защищает URL и сообщения об ошибках автоматически. Значения секретов, полные URL с query и персональные данные нельзя записывать в логи, Sentry или ключи кеша.

## HTTP-транспорт

Реализованный `damia_sdk.transport.HttpClient` переиспользует один `httpx.AsyncClient`, выбирает базовый адрес и ключ по имени сервиса, добавляет ключ в query и отправляет GET. POST пока запрещён: расположение его параметров и ключа у поставщика не подтверждено. HTTP-запрос транспорта — **реальный запрос**, если в настройках указан реальный адрес; он может быть платным или иметь побочные эффекты.

Транспорт и сервисные методы возвращают `HttpResponse` с `status_code`, `content_type`, байтами `body`, признаком `from_cache`, свойством `data` и методом `json()`. Тело не попадает в `repr`; ответ не содержит объекта HTTPX с полным URL. Тело загружается в память целиком; потоковой загрузки пока нет.

Применяются отдельные connect/read/write/pool timeout и предел соединений. Перенаправления отключены, чтобы ключ не был неявно отправлен на другой адрес. `trust_env=False`: системные proxy-настройки HTTPX автоматически не используются. HTTPS обязателен, кроме loopback HTTP для локальных тестов; URL с учётными данными, query и fragment запрещены. Тесты могут подставить `httpx.MockTransport`; `DamiaClient` принимает его через `http_transport`.

`DamiaClient` и `HttpClient` поддерживают `async with` и `aclose()`. Переменные окружения, как и раньше, читаются только при явном `DamiaSettings.from_env()`.

Пример низкоуровневого запроса **только к локальному Prism**, запущенному через `make prism-fns`:

```python
from pydantic import SecretStr
from damia_sdk import BaseURLSettings, DamiaSettings
from damia_sdk.transport import HttpClient

settings = DamiaSettings(
    fns_key=SecretStr("test-key"),
    base_urls=BaseURLSettings(fns="http://127.0.0.1:4010"),
)

async with HttpClient(settings) as http:
    result = await http.request(
        "GET", "/egr", service="fns", params=[("req", "0000000000")]
    )
    print(result.status_code, result.json())
```

Повторы и кеш в этом примере выключены. Для повторов на уровне транспорта задайте `RetrySettings(enabled=True)` и `allow_retry=True`; для кеша — `CacheSettings(enabled=True)`, `allow_cache=True` и проверяющий ответ `cache_validator`. Сервисные методы сейчас не передают эти флаги и не предлагают включать их для отдельных вызовов: изменение одних настроек не включает повторы или кеширование сервисных методов. Это осознанное ограничение: повтор может расходовать квоту, а кеш может содержать конфиденциальные сведения.

SDK не пишет URL в собственные сообщения об ошибках и не сохраняет исключения HTTPX в их цепочке. INFO-записи HTTPX для запросов SDK не содержат query. Query с ключом и параметрами виден серверу, прокси и средствам перехвата сетевого трафика; пользовательский базовый URL считается доверенным. DEBUG-логи нижележащих библиотек, HTTP-интеграции и сбор локальных переменных traceback требуют отдельной настройки приложения для защиты секретов. SDK не меняет глобальные настройки логирования или Sentry.

### Повторы и асинхронный опрос

Повторы по умолчанию **выключены**, так как запросы могут быть платными, а некоторые GET изменяют состояние. Необходимо одновременно включить `RetrySettings.enabled` и передать `allow_retry=True` конкретному запросу. Разрешены только явно перечисленные документированные пути без побочных эффектов. Повторяются сетевые ошибки и статусы 429, 500, 502, 503, 504; ограничены число попыток и общее время, используется exponential backoff с jitter. Числовой и HTTP-date `Retry-After` учитываются; если требуемая задержка превышает настроенный максимум, запрос не повторяется. Некорректные значения, включая буквальные `inf` и `nan`, игнорируются. Переполненное десятичное целое считается бесконечной задержкой: повтор не выполняется, а `retry_after` в исключении равен `inf`.

Операции с побочными эффектами, включая ФНС `mon`, закупки `zmon` и арбитражи `delopro`, нельзя повторять неявно. Ошибки авторизации и валидации также не повторяются автоматически. При тайм-ауте исход запроса может быть неизвестен, даже если клиент не получил ответа.

Опрос асинхронного результата `zsk` — отдельный механизм, а не retry сетевой ошибки. Документация пока не устанавливает интервал и предел опроса.

### Кеширование

Кеш по умолчанию **выключен**. Нужны `CacheSettings.enabled`, явный `allow_cache=True` и `cache_validator`, подтверждающий, что успешный HTTP-ответ безопасно кешировать. Без валидатора 2XX может содержать бизнес-ошибку. Поддерживаются глобальный и запросный TTL, очистка, ограничения количества и размера записей, LRU-вытеснение и single-flight для одинаковых одновременных запросов. Сохраняются только JSON-ответы, прошедшие проверку; ключ кеша — HMAC, а не URL или секрет. `cache_ttl` должен быть положительным; значения с разными TTL не используют одну запись.

Очистка сразу делает старое поколение недоступным. Поколение определяется после получения single-flight lock и проверки кеша, перед сетевым запросом: запрос со старым поколением не восстановит запись, а ожидавший lock до очистки запрос может начать сеть в новом поколении и заполнить кеш. Ошибки удаления не мешают попыткам удалить остальные ключи; неудачные ключи сохраняются для повтора, поэтому временно физическая память может превышать лимит доступных записей. Ошибка очистки сообщается обобщённым исключением. Закрытие пытается освободить кеш и HTTP-клиент, затем сообщает обобщённую ошибку; повтор после ошибки повторяет незавершённые операции.

После начала `aclose()` новые запросы и ожидающие single-flight отклоняются, активные запросы могут завершиться ошибкой и не записывают ответы в кеш. Параллельные вызовы ожидают общее закрытие; отмена одного ожидающего не отменяет освобождение. Общий ключ не включает валидатор: каждый получатель повторно проверяет запись, а несовместимые валидаторы могут вызвать дополнительные сетевые запросы и замену записи. Single-flight сериализует идентичные запросы с одинаковым TTL, но не гарантирует единственный сетевой вызов.

Для кеширования сейчас допускается только `application/json` без учёта регистра и параметров и при положительном валидаторе. MIME не подтверждает корректность JSON или отсутствие бизнес-ошибки. Отдельно `HttpResponse.data` разбирает как JSON также любой тип с суффиксом `+json`, включая `text/example+json`; остальные `text/*` возвращаются текстом, прочие — байтами.

Операции с побочными эффектами, ошибки, неразобранные ответы, персональные данные и файлы не кешируются автоматически. Ключ кеша должен учитывать сервис, метод, параметры и контекст доступа, но не содержать секрет в открытом виде. Значения тоже могут быть чувствительными и требуют соответствующей политики хранения. Отключение кеша задаётся настройками и флагом запроса, а не значением TTL.

Кеш в памяти живёт в процессе. Между отдельными вызовами CLI он не сохраняется; общее или постоянное хранилище — отдельное решение.

### Ошибки

Публичная иерархия от `DamiaError` включает ошибки конфигурации, закрытого клиента, соединения, тайм-аута, HTTP, ограничения частоты и разбора ответа. `DamiaHTTPError` предоставляет статус; HTTP 429 представлен `DamiaRateLimitError`. Сообщения и цепочки исключений не содержат HTTPX-запросы или тела ошибок. Проверка содержимого успешных ответов и типизация бизнес-ошибок DaMIA ещё не реализованы: их формат не установлен.

## CLI

CLI должен вызывать методы SDK, а не выполнять независимые HTTP-запросы. Планируемая группировка:

```text
damia fns egr --req ...
damia fns search --q ...
damia rosstat balance --inn ...
damia banks bankinfo --bankregn ...
damia procurement contracts --inn ...
damia arbitration dela --q ...
damia fssp isps --inn ...
damia spk report --req ... --format json
```

Группы и команды представлены как заглушки. Их опции строятся по сигнатурам явно перечисленных методов SDK; подчёркивания в именах команд и опций заменяются дефисами. Параметры с неуточнённой структурой пока принимаются как строки и не обрабатываются. Заглушки не загружают настройки, не вызывают SDK и не обращаются к API; после разбора параметров они сообщают о незавершённой реализации в stderr и возвращают код 1. Для справки доступны `damia --help`, `damia fns --help` и `damia fns egr --help`; команда `damia version-info` работает.

В дальнейшем CLI должен запускать асинхронную логику на своей точке входа, выводить данные в stdout, диагностику в stderr и возвращать ненулевой код при ошибке. Для файлов нужен явный путь вывода. Изменяющие состояние действия мониторинга должны быть явно названы. Ключи не передаются в аргументах; для чувствительных параметров следует предусмотреть ввод из stdin или файла вместо истории shell.

## Логирование и Sentry

SDK как библиотека не должен добавлять глобальные обработчики Loguru или переопределять настройки приложения пользователя. CLI настраивает логирование в собственной точке входа. Допустимые диагностические поля: сервис, операция, длительность, статус, номер попытки, cache hit/miss — без ключей, полных URL, query, персональных данных и тел ответов.

Sentry — опциональный extra. SDK не должен самостоятельно инициализировать его, отправлять телеметрию без согласия или менять существующую конфигурацию приложения. Для CLI интеграция возможна при явном включении. Необходимо очищать события, breadcrumbs, запросы, трассировки и локальные переменные до отправки; одного `send_default_pii=false` недостаточно. Не допускать дублирования событий Loguru/Sentry. Маскирование проверять тестами на синтетических секретах.

## Тестирование

- `pytest` и `pytest-asyncio` — тесты SDK, политик кеша и повторов, ошибок, отмены и CLI.
- `httpx.MockTransport` — проверка запросов без сети; фиксированные синтетические ответы проверяют разбор, ошибки и конфиденциальность.
- Hypothesis — генерация входов для проверки сериализации, граничных случаев и инвариантов, в том числе против локального Prism.
- Prism — HTTP mock для интеграционных сценариев. Он генерирует ответы по тем же исследовательским спецификациям, поэтому успех тестов сам по себе не доказывает совместимости с DaMIA.
- Живые API-запросы, в том числе кажущиеся читающими GET, выполнять только после отдельного разрешения и проверки стоимости и последствий.

E2E-наборы отдельно проверяют 61 метод SDK и 61 команду CLI против локальных Prism-серверов с генерацией синтетических входов через Hypothesis. Тесты вызывают SDK или запускают CLI отдельным процессом и проверяют запросы через локальный прокси. Тесты SDK проходят; CLI-тесты не помечены `xfail` и ожидаемо падают, поскольку команды не реализованы. Ответы для трёх операций дополнены только в тестовых копиях OpenAPI; эти фикстуры не являются подтверждением контракта DaMIA. Команды и ограничения запуска — в [README проекта](../README.md#тестирование-с-prism).

## План первого этапа

1. Утвердить публичные имена методов и формат возвращаемых результатов.
2. Реализовать настройки, жизненный цикл `DamiaClient`, общий HTTP-транспорт и безопасные исключения.
3. Реализовать первые методы ФНС `egr` и `search` и соответствующие CLI-команды.
4. Покрыть их тестами транспорта, SDK и CLI; проверить локальную работу с Prism.
5. Добавить явно включаемые политики повторов и кеша с тестами безопасности и конкурентности.
6. Поэтапно расширять сервисы и подтверждать схемы поставщика по разрешённым обезличенным примерам.

Полный выпуск заблокирован: CLI e2e входят в обязательный `make check`, а CLI остаётся заглушкой. SDK-only scope и отдельный gate не утверждены. Контракты поставщика, включая ответы `procurement/zmon`, `spk/report` и `spk/proverki`, не подтверждены. Локальная сборка wheel и sdist 0.1.0 и просмотр их состава и метаданных выполнены на Python 3.13.14; установка в чистые окружения с зависимостями и проверка диапазонов ещё не завершены из-за отсутствия `aiocache` в offline-кеше. Исходники и тесты не используют `aiocache` напрямую, но удаление зависимости требует проверки потребителей и совместимости.

Сборка и публикация описаны в [README проекта](../README.md#сборка-и-публикация). `make push` публикует пакет в публичный PyPI и не должен запускаться до проверки имени, версии, прав и содержимого артефактов.
